## Architecture and authority

`gui/drafts.py::SetupReferences` owns opaque registrations; its `identity()` returns basename, SHA-256 and string size. `gui/setup_models.py` defines editable string fields. `gui/setup_validation.py::compile_draft` uses `validation.load_samples`, `schemas.Sample`, `barcodes.Catalog`, geometry and the existing DAG; it returns private `_compiled` science/files and public preview. `gui/execution.py` recompiles/materializes and binds execution. `workflow.py` and `gui/worker.py` perform authoritative verification. `gui/jobs.py` decides terminal state and result registration. `gui/projection.py` presents stored metrics; React is not a scientific authority.

## C/D — Excel matrix and catalog authority

Future auditor first downloads the candidate's official template, records hashes/sheet/header metadata, and binds these semantic cells to that advertised layout. Binding may change sheet/column coordinates only, not silently normalize invalid values. Freeze such transport binding as a separate audit commit.

Accept: one sample, twenty samples, outer cell whitespace, optional blank block_id with paired=false, and QI-HITOM `4A` expansion through existing catalog. Required headers follow backend Sample metadata; sequence columns may be blank in the new catalog-ID convenience path. Preserve replicate `01` as text, not integer 1. A spreadsheet numeric cell that destroyed leading zeros must not invent them.

Strict audit profile rejects interior blank rows/data after a blank row, multiple apparent data sheets, renamed mandatory Samples sheet, hidden data rows/columns, merged data cells, formulas (including cached numeric 6), formula errors and dates in integer fields. These are structural import constraints, not changes to scientific validation. Trailing empty formatted rows may be ignored if no later data is discarded. If official format intentionally supports a structural case, require a documented explicit choice/preview of ALL affected data and a pre-audit contract decision; never silently select first sheet, skip hidden data or stop at first blank. Invalid import is atomic: no partial replacement of draft rows. Valid import produces editable rows; subsequent edits invalidate Review.

## G — final verification

Current authoritative job states are exactly STARTING, RUNNING, CANCELLING, CANCELLED, FAILED, COMPLETED. Stage states also include REUSED and SKIPPED_SCIENTIFIC_GATE. No FINALIZING JobState may be invented.

`workflow.execute_workflow` emits FINAL_VALIDATION after the last stage and before `_verify_stages`/manifest verification. `JobStore._observe` clears current_stage_id at this event, retains RUNNING and completed scientific counts. `worker.run` verifies again before VERIFIED_SUCCESS. `_supervise` requires exit 0, VERIFIED_SUCCESS and containment confirmation; it emits VIEWER_VERIFICATION and disables cancellation at the established finishing boundary before `register_completed`. Only verified workspace registration plus existing cleanup/containment rules allow COMPLETED. VIEWER_VERIFICATION alone is NOT proof of success: current code can emit it on the failure path too.

Freeze browser timelines: active stage RUNNING; all stages terminal scientific statuses but still RUNNING; FINAL_VALIDATION; VIEWER_VERIFICATION with cancellable=false; COMPLETED with workspace_id. During intermediate phases show prominent final-verification/finalization text and completed stage progress without implying elapsed-time prediction or publishing results. On FAILED/CANCELLING/CANCELLED, that status supersedes stale verification text. Reload reconnects to server job+events, handles pagination, duplicate sequence and late/out-of-order response without fabricating completion. Test cancellation both before and after the existing finishing boundary, verification exception, false worker success, no registration and delayed confirmation using retained tests. Do not redesign transitions or recovery to improve presentation.

## O — findings policy

BLOCKING: changed qualified science, arbitrary file access/overwrite, deletion of external inputs, accepted partial upload, broken containment/authentication or false verified completion. MAJOR: silent dropped/changed rows, wrong metric population/denominator, missing required input/UX behavior, stale version provenance. MINOR: non-misleading presentation/accessibility defect with bounded workaround. INFO: documented baseline behavior or audit limitation. Record reproducer, expected/observed, source revision, artifact hashes and scope separately. Known M11C MINOR/INFO findings are out of scope; do not reopen or fix them.

No new confirmed pre-existing defect was found during preparation.
