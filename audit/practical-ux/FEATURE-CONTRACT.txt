Design candidate-independent tests for:

## Normal cases

- valid R1 upload
- valid R2 upload
- R1 + R2
- replacement
- duplicate original filenames
- same filename with different bytes
- same bytes with different filenames

## Streaming/integrity

- sufficiently large synthetic `.fastq.gz`
- verify upload is not whole-file buffered if testable
- exact SHA-256 preservation
- exact byte-size preservation
- registered file equals uploaded bytes
- no truncated upload accepted

## Interrupted upload

Test disconnect/failure at:

- 0 bytes
- first chunk
- middle
- final chunk before finalize
- after temp write but before registration if such a boundary exists

**no partial file may become an accepted Setup input.**

Determine how to inspect application-owned temp/staging leftovers safely.

## Filename attacks

`../../VICTIM.fastq.gz`

`..\..\VICTIM.fastq.gz`

`C:\Windows\System32\VICTIM.fastq.gz`

encoded separator variants

Unicode lookalike separators where relevant

very long filename

leading dot filename

duplicate filename

Expected:

- filename cannot control server path
- no external victim mutation
- no traversal
- no arbitrary overwrite

## Server-path injection

Ensure the API cannot be abused by sending a local Linux path instead of file bytes.

Attempt references to:

`/etc/passwd`

owned workspace files

another analysis input

external legacy `--setup-fastq` file

Expected:

**upload API cannot convert arbitrary server paths into uploaded inputs.**

## Symlink attacks

If feasible, test:

- staging destination symlink
- temp-file replacement
- symlink to external victim
- directory substitution
