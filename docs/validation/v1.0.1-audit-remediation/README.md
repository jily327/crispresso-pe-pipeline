## Design and boundaries

* Scientific runners and calculations remain unchanged. Workflow metrics (PE and nuclease) execute in a private random attempt directory beside the workspace, on the same filesystem. The workflow validates the output before publication.
* A single atomic HMAC receipt records the candidate inventory and directory device/inode before Linux `renameat2(RENAME_NOREPLACE)` publication. An interruption after rename and before stage completion requires explicit metrics force, backed by that independent ownership record. Stage metadata is authenticated before its atomic write. Normal completion retires the temporary publication proof.
* Failed and hard-killed attempts remain outside the final workspace. They are **retained diagnostics**, not automatically deleted. Resume neither consumes nor deletes them, including planted files. This trades disk space for deletion safety. Inspect them before any manual housekeeping; do not use wildcard recursive deletion. Direct standalone M4 calls retain their existing diagnostic-output behavior; transaction publication applies to workflow/GUI runs.
* Recovery still requires an exclusive workspace lock and valid signing credentials. Unexpected files block force. Force now removes only individually inventoried files using no-follow directory descriptors and nonrecursive rmdir; a late foreign file cannot be swept up by recursive removal.
* v1.0.0 nonempty interrupted final output has no independent ownership inventory. It remains unsupported. Preserve it and rerun into a fresh workspace from the original input files. Do not copy a receipt from another workspace or manufacture a new inventory. F-01 is therefore **partial across historical workspaces**, not universally resolved.
* A hard process kill can leave the pre-existing M7 lock. Automatic lock removal remains prohibited. Confirm no supervisor/backend is active and follow the documented stale-lock procedure before recovery. A live or uncertain owner means wait, not force.

## Changes to pre-existing tests

The former empty-orphan metrics test now writes nonempty output and expects ordinary resume because the attempt is outside the final workspace. Existing foreign-file tests retain their exact refusal/no-mutation assertions; only the misleading TAMPERED label changes to UNSUPPORTED (symlink/known corrupted metadata checks remain distinct). HMAC-forgery tests still refuse all recovery/deletion but expect RECOVERY_AUTHENTICATION_FAILED because an HMAC mismatch alone does not prove malicious modification. The missing-key test hides both persistent and legacy credential locations. Version assertions move to 1.0.1. No scientific expected value or backend-gated skip was weakened.

The qualified daemon reported container/image ID `sha256:518eb6dd6672f4edee8ec464b75d7555cf04ca185ce1ca676d7b930bde24655d`, repository digest `pinellolab/crispresso2@sha256:b7e7971a87769aa584d31d21e199a9abca5f641c4f889c2e807cb6324fc8ce0c`, CRISPResso 2.3.4 and fastp 1.3.3. The qualification wrapper uses this local, network-disabled container. These observed facts are recorded in evidence/docker-runtime.json. They do not establish automatic attestation of arbitrary laboratory wrappers or equivalence to other version-matching installations.

Authorized legacy resume also persists its authenticated credential. If a different primary key already exists, it is preserved unchanged and the original credential is saved as `legacy-<nonsecret SHA-256 key ID>` in the same private recovery directory. Read-only inspection never creates or migrates keys. Receipts signed before migration remain recoverable through the archived original key after `/tmp` cleanup. Already-lost original credentials cannot be reconstructed.

The original defect harness was repeated against the isolated correctly versioned v1.0.0 installation; `evidence/baseline-reproductions-corrected-version.json` confirms the same nonempty recovery dead end, false regenerated-key TAMPERED label and padded-export failure with `software_version: 1.0.0`.

`reproduce_baseline.py` preserves that executed harness. Run it from the repository root with the audited baseline installed, `PYTHONPATH` selecting that installation, and the qualified wrapper at the recorded path. Its fixed `/tmp/pe-baseline-qualified` destination must not already exist; use an isolated disposable qualification environment. It creates synthetic data and a separate replacement credential to test the old authentication behavior. It is evidence tooling for v1.0.0, not a recovery operation for user workspaces. The synthetic fixture and Fable oracle scripts are pinned by the baseline and artifact SHAs above.

Final review also covered interrupted invalidation: already-removed authenticated subdirectories are skipped on repeated force, while newly planted files still prevent directory removal. Key creation now uses descriptor-relative exclusive rename so process death cannot leave a two-link key between hard-link publication and temporary-name cleanup. Concurrent initialization and death immediately after key publication have explicit regression tests.

The separately gated GUI cancellation regression uses a qualification-only container-side guard that watches a kernel file lock held exclusively by its local wrapper. The guard terminates its owned Core process when the wrapper dies, including SIGKILL, then exits. It pauses genuine CRISPResso after observing nonempty backend files, cancels through the actual GUI API, independently checks stopped Docker state, and resumes through the actual Recovery API.

Three earlier qualification-wrapper runs failed (one passed test and one failed test each). Ordinary Docker CLI signal proxying and a host-side SIGTERM cleanup handler were insufficient. The third run explicitly observed Docker `State.Running == true` after GUI cancellation. Workflow unwind through Python `subprocess.run` can kill its direct wrapper before a signal handler executes. The final test therefore uses owner-death detection inside the container; no production scientific runner or supervisor was changed to conceal this deployment limitation. The product's external laboratory wrapper must be separately qualified for daemon-process containment, including abrupt owner death. Neither `docker run --sig-proxy` nor reusable `docker exec` is assumed sufficient. Kernel-lock sharing was tested on this Linux Docker filesystem, not on Windows/WSL.
