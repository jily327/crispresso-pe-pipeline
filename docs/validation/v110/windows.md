# Local Windows / WSL2 qualification for the 1.1.0 candidate

Record Windows, WSL distribution, Docker Desktop, Python, Node, candidate commit, wheel SHA-256 and CRISPResso image digest with the run. Preserve the v1.0.1 installation, credential store and result folders. Use a new, user-owned WSL checkout and a candidate-specific output directory.

1. Build the candidate wheel from the archived frontend sources and checked assets. Run the release desktop installation in a separate installation root. Start the installed launcher from Windows, including a path with spaces, and confirm its package version and runtime probe report 1.1.0 and CRISPResso 2.3.4. Record the image digest `sha256:b7e7971a87769aa584d31d21e199a9abca5f641c4f889c2e807cb6324fc8ce0c`. [Desktop installation and recovery](../../desktop-1.0.md)
2. Open an existing verified v1.0.1 workspace with its original persisted recovery identity. Record scientific verification, stage inventories and original hashes on opening and after closing the viewer. Check access to its existing result and workbook under its historical version folder.
3. Create a fresh two-site workflow through Setup. Import paired reads, declare the empty PCR negative control, enter the supplied references, the actual experimental guide fields and separate R1/R2 trim counts. Confirm normalized strand, copy diagnostics and predicted window before execution. For a synthetic acceptance test, use the recorded synthetic inputs and label the resulting workspace accordingly.
4. Run to completion in Docker Desktop. Compare demultiplexed and prepared counts, zero-control status, combined and copy-specific integer partitions, unresolved reads, actual backend windows and fractions against the same-input Linux records. Check the explicit outside-window case. Export Excel and compare stored numerator/denominator cells, biological SD and unavailable values with the GUI. Run final scientific verification as well as workbook verification.
5. Repeat with a two-copy nuclease fixture for W2 and a separate exploratory W3 run. Compare their independently recorded site counts, ambiguous cohorts and per-copy coordinates. Retain the primary result during the comparison.
6. Interrupt a disposable synthetic analysis during the backend stage, verify the child Docker job exits, then exercise normal recovery and final verification. Check that an unrelated container and the historical result remain intact. Rerun from the same inputs in a new workspace and compare integer counts, allowing recorded execution timestamps and paths to differ.

Keep the Windows manifests, hashes, integer comparisons and any discrepancies with the local qualification record. Linux cloud results and archived Windows v1.0.1 results have separate qualification scopes.
